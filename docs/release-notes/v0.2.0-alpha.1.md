# KeenySpace v0.2.0-alpha.1

A hardening release. Every change below came out of a full review of the code, the
build and the deployment; the sections after this intro are assembled from the
branches that landed since v0.1.0-alpha.1.

Still alpha: expect breaking changes between alpha releases.

## Upgrade first, read later

This release **will not start** on a v0.1.0-alpha.1 configuration, by design.
Follow [docs/upgrade.md](../upgrade.md) before pulling. The short version:

1. Put your existing secrets into `deploy/.env` — compose now refuses to start
   without them, and `POSTGRES_PASSWORD`, `AUTHENTIK_DB_PASSWORD` and
   `AUTHENTIK_SECRET_KEY` are baked into volumes you already have. Changing
   `KEENYSPACE_API_KEY_PEPPER` invalidates every existing `ks_live_*` key.
   `deploy/gen-secrets.sh` fills only what is missing.
2. Move any `KEENYSPACE_*` app overrides from `deploy/.env` to
   `deploy/keenyspace.env`; the app container no longer receives the whole file.
3. Add your users, including `akadmin`, to `keenyspace-users`, and your operators
   to `keenyspace-admins`. Both gates are on by default now.
4. `docker compose -f deploy/docker-compose.yml up -d --build --remove-orphans`
   (Redis is gone; `--remove-orphans` clears it). Migrations 0004 and 0005 run on boot.
5. Every API-key owner authenticates once via OIDC (`keenyspace login`) so the
   server records their group snapshot; until then their keys are refused.

## What is breaking

- **Admin endpoints require the `keenyspace-admins` group**, in addition to
  `KEENYSPACE_ADMIN_API_ENABLED=1`. Previously any authenticated caller could
  back up or restore the whole deployment.
- **API keys are group-gated and can expire**; they can no longer mint other keys.
- **Compose fails closed on secrets**, and the app, Authentik and Postgres ports
  are bound to loopback. Caddy is the public entry point.
- **Prometheus metrics moved to an internal port** (9100 by default); `/metrics`
  on the API port now requires authentication. Five MCP metric labels lost their
  `_tool` suffix, so dashboards querying them need updating.
- **Backups declare `0.2.0-alpha.1`**, so restoring a v0.1.x archive needs `force=true`.
- **Empty `append_log` content is rejected** with 422 instead of silently
  corrupting the log.

## Worth knowing

- Two data-loss paths are closed: a forced restore used to wipe the database and
  the vault before validating the archive, and an empty WAL entry used to swallow
  the next one.
- An uploaded dump can no longer carry psql meta-commands, which were a shell on
  the server.
- The `blueprint` field on workspace create was a path traversal that could copy
  any server-readable directory into a vault and hand it back through export.
- Compile survives crashes: an interrupted pass replays its recorded intent
  instead of paying the model twice, and a backlog is compiled in bounded chunks
  instead of pausing forever.
